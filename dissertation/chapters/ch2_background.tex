\chapter{Background and Related Work}
\label{ch:background}

This chapter surveys the literature that motivates and contextualises the work in this
dissertation.
It proceeds from the industrial context --- the prevalence and security consequences of
polyglot software development --- through the evolution of vulnerability detection methods,
to the specific pre-trained code models, graph neural network approaches, benchmark
datasets, and calibration techniques on which the experimental design draws.

\section{Polyglot Software Development and Security Implications}

Modern software projects are routinely written in multiple programming languages.
Surveys of professional developers consistently report that the majority of teams maintain
codebases spanning four or more languages simultaneously, with system-level logic in C or
C++, application logic in Python or Java, and scripting or infrastructure components in
shell or YAML~\citep{mayer2017multilanguage}.
An empirical study of open-source repositories found that approximately 80\% of
non-trivial projects contain at least seven distinct languages when configuration, build,
and documentation artefacts are included~\citep{yang2023demystifying}.
The trend is accelerating: \citet{mussbacher2024polyglot} characterise polyglot
development as the default mode of contemporary software engineering rather than an
exceptional practice.

This diversity creates compounded security risk.
Vulnerability patterns are not uniformly distributed across languages: memory corruption
defects (buffer overflows, use-after-free, null dereference) are predominantly
C/C++ phenomena; injection vulnerabilities (SQL injection, command injection, path
traversal) manifest in every language but through language-specific APIs; and logic
errors such as race conditions present structurally different surface forms depending on
the concurrency model the language provides~\citep{sakharkar2023systematic}.
A vulnerability management framework must therefore either operate language by language
--- requiring separate tools and separate expertise --- or provide a unified detection
capability that generalises across languages~\citep{syed2020cybersecurity}.
Static analysis tools such as Flawfinder~\citep{wheeler2004flawfinder} address individual
languages but do not transfer, and empirical studies of practitioner experience report
that the overhead of managing multiple tools is a primary barrier to adoption in
industrial workflows~\citep{johnson2013don}.
The goal of cross-language vulnerability detection addresses this barrier directly.

\section{Deep Learning for Vulnerability Detection}

The application of deep learning to vulnerability detection began with sequence-based
models operating on tokenised source code.
VulDeePecker~\citep{li2018vuldeepecker} represented code as sequences of program slices
and applied a bidirectional LSTM to classify each slice as vulnerable or safe, demonstrating
that neural networks could learn useful vulnerability representations without hand-crafted
features and establishing the function-level binary classification framing used in
subsequent work.
SySeVR~\citep{li2022sysevr} extended this with semantics-preserving intermediate
representations covering a broader range of CWE categories simultaneously.

A parallel line of work applied graph representations rather than sequences.
\citet{zhou2019devign} introduced Devign, which represents each function as a joint graph
combining the control-flow graph, data-flow graph, and abstract syntax tree, and applies
a gated graph neural network to classify the combined structure.
\citet{chakraborty2022reveal} examined whether deep learning vulnerability detectors had
reached practical utility, finding that the generalisation gap between within-distribution
benchmarks and real-world code remained large for all architectures tested, and identifying
data imbalance and distribution shift as the primary bottlenecks.
The scale of vulnerability data available from open-source repositories continues to grow,
providing new opportunities to close this gap through better training corpora~\citep{xu2022detecting}.

\section{Pre-Trained Transformer Models for Code}

The introduction of BERT~\citep{devlin2019bert} established masked language modelling as
an effective self-supervised pre-training objective, yielding representations that transfer
to downstream tasks with minimal fine-tuning.
\citet{rogers2020bertology} provide a comprehensive empirical survey of what BERT-family
models learn, confirming that the attention mechanism~\citep{vaswani2017attention}
acquires structured knowledge --- syntactic dependencies, co-reference chains, semantic
roles --- during pre-training rather than from fine-tuning supervision alone.
The success of BERT prompted the development of code-specific pre-trained models that
apply the same approach to programming language corpora.

\textbf{CodeBERT}~\citep{feng2020codebert} was the first large-scale code pre-trained
model, trained on a bimodal objective over code--docstring pairs from GitHub across six
programming languages.
Its pre-training on a multi-language corpus gave it representations that transfer across
language boundaries, and fine-tuning on vulnerability detection tasks produces competitive
results that substantially outperform sequence-based RNN models on BigVul and Devign
benchmarks.

\textbf{GraphCodeBERT}~\citep{guo2021graphcodebert} augments the token-level transformer
with data-flow edges derived from program analysis.
During pre-training, additional attention heads learn to attend over data-flow
relationships, producing representations that encode which variables a token depends on.
This architectural modification improves performance on tasks requiring understanding of
value propagation, including clone detection and vulnerability detection on
data-flow-sensitive CWE classes.

\textbf{CodeT5}~\citep{wang2021codet5} adopts an encoder-decoder architecture and
introduces an identifier-aware pre-training objective that trains the model to predict
masked identifier tokens using knowledge of their structural role.
The encoder-decoder design supports both understanding tasks (classification, retrieval)
and generation tasks (summarisation, repair), achieving state-of-the-art results across a
broad task suite.

\textbf{UniXcoder}~\citep{guo2022unixcoder} unifies encoder-only, decoder-only, and
encoder-decoder modes in a single architecture by conditioning the attention mask pattern
on the task at inference time.
Pre-training incorporates abstract syntax tree information serialised as a prefix sequence,
allowing the model to attend to syntactic structure without requiring a separate graph
encoder.
UniXcoder achieves competitive results across code understanding and generation benchmarks
and is selected as the base model for this dissertation.
Its ability to incorporate AST structure at pre-training time, combined with its
single-architecture flexibility, makes it well-suited to fine-tuning for binary
vulnerability classification.

\textbf{LineVul}~\citep{fu2022linevul} applies a transformer encoder with a
classification head to function-level vulnerability prediction and introduces an
attention-based line-level attribution method that highlights which lines contributed most
to the prediction.
LineVul achieves F1 scores above 0.90 on the BigVul benchmark, establishing the
importance of reporting not only function-level verdicts but also line-level explanations
for practical tool integration.

\section{Graph Neural Network Approaches}

Graph neural networks provide an alternative to sequence-based encoding by operating
directly on graph representations of program structure.
\citet{zhou2020gnn} survey GNN architectures and demonstrate that message-passing over
structural edges produces representations that are qualitatively different from sequential
attention over token streams.

\textbf{LineVD}~\citep{hin2022linevd} applies graph neural networks at the statement
level, constructing a program dependence graph and classifying individual statements rather
than whole functions.
Statement-level classification is more precise for audit support but requires line-level
ground truth labels, which are absent from most function-level vulnerability datasets.

\textbf{BGNN4VD}~\citep{cao2021bgnn4vd} constructs a bidirectional graph encoding both
forward and backward data-flow edges, allowing the model to propagate information from a
vulnerable sink backwards to its taint source and forwards from a taint source to its
dangerous sinks.
The bidirectional design improves recall on taint-sensitive classes where the vulnerability
is distributed across multiple statements.

The comparative evidence from these studies establishes that graph-based models
consistently outperform sequence-based models on CWE classes whose exploitability depends
on inter-statement reasoning --- use-after-free (CWE-416), taint tracking for injection
(CWE-78), and null pointer dereference (CWE-476) --- while sequence-based models match or
exceed graph-based models on classes with compact, locally recognisable patterns such as
hardcoded credentials (CWE-798) and insecure hash algorithm selection (CWE-327).
This complementarity motivates the semantic understanding test suite in this dissertation,
which is designed to locate the boundary between pattern-matching and structural reasoning
for sequence models, and to characterise the architectural ceiling precisely rather than
simply observing it in aggregate benchmark results.

\section{Benchmark Datasets}

The quality of vulnerability detection research is constrained by the quality of its
benchmark datasets.
Four datasets are relevant to this work.

\textbf{BigVul}~\citep{fan2020bigvul} is a C/C++ dataset of 3{,}754 vulnerabilities
sourced from real-world CVE fixes in open-source repositories, paired with the pre-fix
(vulnerable) and post-fix (safe) function versions.
The paired structure makes BigVul suitable for minimal-fix testing and for learning the
specific changes that resolve a vulnerability.

\textbf{DiverseVul}~\citep{ni2023diversevul,chen2023diversevul} extends BigVul in both
scale and CWE diversity, providing approximately 18{,}000 vulnerable and 330{,}000 safe
C/C++ functions spanning approximately 150 distinct CWE types.
DiverseVul includes structured CWE annotations that make it possible to evaluate
per-class recall rather than only overall accuracy.
It is used in this dissertation for real-world augmentation (1{,}000 training samples
from \texttt{sample\_train.jsonl}) and real-world evaluation (200 samples from
\texttt{sample\_test.jsonl}).

\textbf{Devign}~\citep{zhou2019devign} provides function-level labels for C functions
drawn from QEMU and FFmpeg, with roughly balanced vulnerable and safe classes, and is
widely used as a benchmark for graph-based vulnerability detectors.

\textbf{DeVAIC}~\citep{cotroneo2025devaic} is a recently introduced benchmark for
evaluating the security of AI-generated code.
DeVAIC provides ground-truth labels for code snippets produced by large language models,
addressing the emerging challenge of detecting vulnerabilities in LLM-assisted development
workflows --- a deployment context that synthetic training data alone cannot represent.

A notable gap across these datasets is Python coverage.
BigVul and DiverseVul are almost exclusively C/C++; large-scale function-level Python
vulnerability datasets comparable in size and annotation quality do not currently exist.
This gap directly motivates the synthetic data approach used in this dissertation.

\section{Calibration of Neural Classifiers}

A vulnerability detector's practical value depends not only on classification accuracy
but on the trustworthiness of its confidence outputs.
\citet{guo2017calibration} demonstrated that modern neural networks are systematically
over-confident and introduced temperature scaling as a simple post-hoc recalibration
method: dividing logits by a learned scalar $T > 1$ before applying the sigmoid flattens
the output distribution, reducing over-confidence without retraining.

\citet{muller2019label} showed that label smoothing achieves a similar calibration effect
during training itself, by replacing one-hot training targets with soft targets that assign
small probability mass to non-target classes.
For binary classification with smoothing parameter $\varepsilon$, hard targets
$y \in \{0,1\}$ become $\tilde{y} = y(1-\varepsilon) + \varepsilon \cdot 0.5$.
Label smoothing produces models that require less post-hoc recalibration than
unsmoothed equivalents.
This result motivates the use of label smoothing ($\varepsilon = 0.1$) in the training
procedure of this dissertation; the near-unity temperature found during post-hoc
calibration ($T = 0.981$) directly confirms that label smoothing has already done most
of the calibration work.

\section{Summary}

Four conclusions from the literature directly shape the design of this dissertation.
First, polyglot codebases are the industrial norm, and vulnerability patterns are
language-specific in their surface realisation even when conceptually shared, motivating
joint multi-language training rather than independent monolingual models.
Second, pre-trained transformer models offer the strongest general-purpose code
representations available, with UniXcoder providing the best combination of structural
awareness and architectural flexibility for fine-tuning as a vulnerability classifier.
Third, sequence models hit a predictable ceiling on CWE classes requiring inter-statement
reasoning, while graph-based models address that ceiling at the cost of language-specific
tooling; the two paradigms are complementary rather than competing, and precisely locating
the ceiling of sequence-based approaches is itself a research contribution.
Fourth, label smoothing is an effective in-training calibration mechanism whose
effectiveness can be verified post-hoc through temperature scaling.
These conclusions define the experimental questions and design choices described in
Chapter~\ref{ch:methodology}.
